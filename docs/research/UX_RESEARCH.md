## 1. 系统性的问题：AI 生成设计的同质化

`[本次核验]` GitHub 项目 **Nutlope/hallmark**（MIT，25k+ ★）的存在本身就是这个问题的证据。
它把「AI 味」拆成 **58 项 anti-slop 检查**，明确把以下东西列为反例：

```
紫粉渐变 Hero
整页居中
Inter 一把梭
圆角图标三卡片
「左 Logo / 中导航 / 右 CTA」的标准 AI 导航
```

**为什么重要**：这说明「AI 生成的设计趋同」不是一个模糊的抱怨，而是**可枚举的
具体模式集合**——因此可以被主动避免。

**对 Lover-page 的直接意义**（这是本轮最重要的 UX 结论）：

> 本项目最大的同质化风险**不是**颜色或字体，而是
> **「八章都活在同一个白色面板卡里」** —— 也就是「同一个模板换配色」的构图版本。

本轮已就此采取行动：`container.dissolveSteps` + `modern-paper` 的无面板构图。
详见 ADR-003 / ADR-005。

**不能复制的**：hallmark 的 21 套主题是它自己的资产，且它主张「纯文字排版、
CSS 画图优先、图片仅在 brief 明确要求时才上」—— 对 Lover-page 不适用
（照片与语音信件是本项目的核心情绪载体，不是可选装饰）。

## 2. 滚动叙事与编辑设计

### CSS Scroll-driven Animations

`[本次核验]`

| 项 | 值 |
|---|---|
| 特性 | `animation-timeline: scroll()` / `view()` + `animation-range` |
| 支持 | Chrome/Edge 115+ 完整；Safari 18 起部分；Firefox 尚未 |
| 关键优势 | **运行在合成器线程** —— 即使 JS 阻塞主线程，滚动动画仍保持 60fps |
| 传统做法的代价 | 监听 `scroll` + `scrollTop` 计算 + throttle/debounce + `IntersectionObserver`，低端机上掉帧 |

**哪里值得借鉴**：`animation-range: entry 20% cover 50%` 这种**视线进入范围驱动**的
淡入，天然适合「一章一章展开」的叙事节奏，而不是「一次性全部出现」。

**可以直接采用**：用 `@supports (animation-timeline: scroll())` 做渐进增强，
不支持时退化为静态呈现。

**不能采用**：**不要加 polyfill**。`scroll-timeline.js` 是运行时 JS 依赖，
会破坏本项目的零依赖方向。宁可让老浏览器看到静态版本。

**对应章节**：叁 · 想问你（引文逐句浮现）、伍 · 私人档案（照片进入视口时的揭幕）、
未来陆 · 时间轴。

### Snow Fall 类叙事（NYT）

`[既有认知]` 核心不是特效，而是**节奏控制**：文字块与视觉块交替呼吸，
每个滚动单位只承担一个信息点，视差用来建立纵深而不是炫技。

**哪里值得借鉴**：「一个滚动单位 = 一个信息点」这个约束。
可以直接用来诊断当前各章是否信息过密。

**不能复制的**：Snow Fall 的视差是绑定 `scroll` 事件的 JS 实现，
且页面总量极大。本项目应使用 CSS `animation-timeline`（见上）并且**极少量**。

**对应章节**：未来陆 · 时间轴。

## 3. 第一屏（Hero / Opening）

### Museum opening / 展览序厅

`[既有认知]` 画廊的序厅不做「所有作品缩略图网格」，而是：
**一件主作品 + 一块展签 + 大量留白**。观众的视线路径被刻意限制为一条。

**哪里值得借鉴**：
- 一屏只放**一个**视觉焦点（本项目 = Redouté 玫瑰）
- 标题的**字距**承担仪式感（当前 `0.22em` 是对的方向，见 §23「不要改成斜体」的约束）
- 留白是构图的一部分，不是「没排满」

**本项目当前的实际判断（浏览器实测）**：
第一屏的结构是对的（玫瑰 → 标题 → 副题 → 进入），
**最弱的一环是「进入」按钮** —— 它原本用硬编码的浅色 wash + 深色描边，
在暗色主题下渲染成一块与深色环境格格不入的灰白矩形。
本轮已令牌化并验证修复。

**不能复制的**：不要把「展签」照搬成「作品名 / 年代 / 材质 / 尺寸」的四行信息栏 ——
私人情感网页的「作品」是**关系**，不是物件。加信息栏会立刻变成美术馆仿制品。

### Luxury editorial / 高端编辑设计

`[既有认知]` 特征：**极大的字号对比**（display 与 caption 相差 4–6 倍）、
**严格的栅格**、**每页一个视觉锚点**、**黑色/米白/一个强调色的三色限制**。

**可以直接采用**：字号对比（已通过 `--fs-*` 令牌实现：`display-xl` 到 `folio`
跨 4 倍以上）；三色限制（当前 `--paper` / `--ink` / `--accent` 系列正是这个结构）。

**对应章节**：第一屏、叁 · 想问你。

## 4. 信件与档案类界面

### Letters of Note 类档案排版

`[既有认知]` 核心手法：
- 原始文本以**接近原貌的排版**出现（信纸感、不居中、左对齐）
- 元信息（日期、收件人）用**小号大写 + 宽字距**，与正文形成层级
- 一个细节（笔迹、折痕、邮戳）承担全部「真实性」

**哪里值得借鉴**：**左对齐 + 小号元信息 + 一个材质细节**。
本项目「陆 · 来信」的 `.letter-card` 目前是**居中容器里的一个带边框的盒子**
—— 边框让它读起来像表单字段而不是信纸。

**已知问题（未修，见 `CURRENT_STATE.md` §6）**：信件章缺少
「日期 + 署名 + 纸材质」这三样让它成为「一封信」的东西。

**不能复制的**：不要引入手写字体。中文手写 webfont 体积巨大且可读性差，
且会把「私人感」做成「可爱感」—— 与艺术方向冲突。

### 美术馆展签（wall label）

`[既有认知]` 标准展签是**两到三行、左对齐、小号、无边框**，
信息层级是「作品名 / 媒介信息 / 一句说明」。

**可以直接采用**：照片章的 `.photo-plate`（`date · place` + `序号 / 总数`）
正是这个结构，且已经不使用卡片。

**对应章节**：伍 · 私人档案。

## 5. 移动端沉浸体验

`[既有认知]` 关键约束：
- 拇指可达区（屏幕下半部）承载主行动
- 44px 最小命中区（本项目已作为硬约束，`@diag` 的 `underSizedTargets: []` 看护）
- 横向滑动用于「同质内容之间的移动」（照片之间），纵向滚动用于「章节之间」
- 手势不能与浏览器手势冲突

**可以直接采用**：
- 照片章 = 纵向章节 + 横向滑动看图 + 点击进灯箱（三层交互，各有明确归属）
- 联系印样用原生 `scroll-snap`，不劫持滚动

**不能采用**：不要做「自定义滑动手势驱动章节切换」。
纵向章节切换已经由按钮 + View Transitions 完成，加手势会与浏览器的
返回手势/滚动冲突，且降低可预测性。

## 6. 明确的「不要做」清单（依据 §22）

综合以上，Lover-page 的视觉目标应当排除：

```
❌ 通用情人节网页（红心 / 粉红渐变 / 心形气球）
❌ AI 生成式构图（整页居中 + 紫粉渐变 + Inter + 三卡片）
❌ 美术馆仿制品（把关系做成展品档案）
❌ 可爱化（emoji 装饰、手写字体、圆角气泡）
❌ 游戏化（积分、成就、进度条奖励、音效反馈堆叠）
❌ 特效炫技（粒子、霓虹、光标跟随、巨幅视差）
```

**目标方向**（§22 原文的展开）：

```
艺术展览（一件作品 + 留白 + 展签）
  + 编辑设计（字号对比 + 栅格 + 单色强调）
  + 博物馆档案（元信息小号 / 宽字距 + 材质细节）
  + 私人信笺（左对齐 + 日期署名 + 纸感）
  + 现代移动交互（拇指区 + 44px + 原生手势）
```
